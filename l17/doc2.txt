# Project Shiva — Exhaustive Documentation

Shiva (binary name `shiv`) is a Linux, io_uring-based advanced TCP/ICMP scanner: raw sockets, ARP, IPv6, traceroute, service/version detection, network-namespace isolation, public-database enrichment, a broad set of scan types, advanced packet manipulation, and high-performance concurrency. This document is the single authoritative reference for every feature and behaviour implemented in the repository — CLI options, internal data structures, file responsibilities, exact behaviours of important functions and modules, design rationale, operational guidance, tuning recommendations, and troubleshooting.

## 1 — Port state determination

### Reference: TCP 3-way handshake (normal)
```
Client                      Server
  | --- SYN (connect) --->   |
  |                          |
  | <--- SYN/ACK (reply) --- |
  |                          |
  | --- ACK (complete) --->  |
  |                          |
(connected)
```

**open**
- Condition: the scanner receives a SYN/ACK in response to a SYN.
- Meaning: the port is accepting connections.
- Typical scan: `-sS` (SYN scan).
- Behaviour: after receiving a SYN/ACK the scanner normally sends an RST to terminate the connection instead of completing the full handshake, unless `-G` is set — in which case it completes the handshake and closes gracefully inside the isolated namespace (see §7.7).
  ```
  Scanner(Client)             Target(Server)
    | --- SYN (probe) --->     |
    |                          |
    | <--- SYN/ACK (reply) --- |
    |                          |
    | --- RST (terminate) -->  |
    |                          |
  ```

**closed**
- Condition: the scanner receives an RST in response to a probe (commonly after a SYN).
- Meaning: the port exists on the host but is not accepting connections.
  ```
  Client                      Server
    | --- SYN (probe) --->     |
    | <--- RST (reject) -----  |
  ```

**filtered**
- Condition: no response is received (the probe is dropped), or an ICMP admin-prohibited message is received. The latter is now specifically classified rather than lumped in with silence — see `icmp_filter_reasons` / `icmp_warnings` on `RecPross`.
- Meaning: a firewall or filter is blocking probes to that port.
  ```
  Client       Firewall        Server
    | --- SYN ---> | --X-->     |
    |              | (drop)     |
    | <--- NONE ---|           |
  ```

**unfiltered**
- Condition: observed when performing an ACK scan (`-sA`) — the target responds with an RST to an ACK probe.
- Meaning: the host/port is reachable but the ACK scan alone does not indicate open vs. closed.
  ```
  Client                      Server
    | --- ACK (no prior SYN) -> |
    | <--- RST (no such conn) - |
  ```

**confused**
- Condition: inconsistent or unexpected responses, often seen with non-SYN scans (XMAS `-sX`, NULL `-sN`, FIN `-sF`).
- Meaning: the scanner cannot reliably classify the port; OS/firewall behaviour is inconsistent.

### Practical guidance
- Use the default SYN scan (`-sS`) for fast, reliable open-vs-closed detection.
- If a port is **filtered**, run an ACK scan (`-sA`) to check reachability, and check `--debug demux` / the `icmp_filter_reasons` output for a specific reason.
- If you see **confused** results, try SYN/ACK/ACK variations or `--debug strack`/`--debug rtt` for more evidence, and consider increasing `--port-timeout`.
- Combine multiple scan techniques and adjust timeout/retry/congestion-tuning knobs (§14) to improve confidence.

### Short examples
- SYN scan (default): `sudo ./shiv 192.168.1.71 -p 1-1000 -sS`
- ACK scan to check filtered ports: `sudo ./shiv 192.168.1.71 -p 80 -sA`

These classification rules match the `RecPross` fields (`open_ports` / `closed_ports` / `filtered_ports`) used throughout the rest of this document.

## 2 — Quick summary

Shiva is a direct, raw-packet scanner for Linux built on io_uring for high-throughput asynchronous send/receive. It combines: many TCP-flag scan types; a stateful 4-way-handshake mode that runs automatically inside an isolated network namespace to suppress kernel RST interference; ARP-based host/MAC discovery; IPv4 *and* IPv6 targets, including hand-crafted IPv6 extension-header chains (Hop-by-Hop, Destination Options, Routing, AH, ESP, Flow Label manipulation); 802.1Q/QinQ VLAN tagging and custom Ethernet framing; IP/ICMP fragmentation with reassembly-evasion variants; checksum-corruption experiments; custom TCP options (TFO cookie injection, TCP-AO, MPTCP MP_CAPABLE, timestamps, MSS, window scaling, SACK); a non-blocking, TLS-capable service/version-detection engine (`-sV`); a traceroute implementation with MPLS label decoding and GeoIP/ASN enrichment; TTL/window-size anomaly analysis for OS fingerprinting; adaptive rate/jitter/batch-delay/bandwidth pacing with congestion-aware retry timing; and integration with public databases (Shodan InternetDB & SecurityTrails). It uses thread-local buffer pools, a fast concurrent queue, and global registered io_uring send/receive rings (with optional SQPOLL) to minimize per-packet overhead and maximize throughput.

## 3 — Feature checklist (exhaustive)

**IO & performance:**
- Asynchronous I/O via io_uring for send and receive, using **global, registered (fixed-fd) rings** shared across worker threads rather than one ring per thread.
- Configurable send/rcv io_uring depths (`--send-uring`, `--rcv-uring`; allowed set 2,4,6,8,16,32,64,128,256,512,1024,2048,4096, default auto).
- Optional `--sqpoll` (kernel-thread submission) — auto-enabled either when adaptive/dynamic pacing is active and probe volume (hosts × ports) crosses `--sqpoll-threshold` (default 300000), or when fixed/non-dynamic pacing is active and the estimated scan duration reaches 8s (`estimate_scan_duration_ms`); falls back gracefully if SQPOLL/ATTACH_WQ setup fails.
- Adaptive pacing: `--rate`, `--jitter`, `--batch-delay`, `--bandwidth`, each with fixed or randomized-range values, plus dynamic/adaptive bounds (`--rate-dyn-min/max/window`, `--batch-delay-dyn-min/max`).
- Congestion-aware retry-delay tuning: `--retry-delay-min/max`, `--retry-delay-floor-div`, `--cong-curve`, `--cong-alpha-up/down`, `--rto-mult`, `--rto-pad1/2`.
- `--buf-peak`, `--batch-settle` for buffer-pool and io_uring batch-submit tuning.
- Fallback send (`sendmsg`) if io_uring submission is unavailable.

**Packet construction:**
- Raw IPv4 **and IPv6** header building, dual-stack aware (`is_ipv6` on `PacketTask`, `sockaddr_in`/`sockaddr_in6` both carried).
- IP fields: src/dst, TTL, flags, ID (including selectable IP-ID generation strategy), DSCP/TOS, Router Alert option, IP Security Option (IPSO).
- TCP fields: src/dst ports, seq/ack, TCP flags, window, URG/PSH, etc.
- TCP options: MSS, Window Scale, SACK permitted, Timestamp (TSval/TSecr), NOP padding, **TCP-AO (kind 29)**, **MPTCP MP_CAPABLE (kind 30)**.
- TCP Fast Open cookie injection with multiple encodings (`len:`, `str:`, `hex:`).
- `--packet-length` — pin the real on-wire packet size (pads with nulls above natural size, truncates payload/options below it; floor 40 bytes).
- Custom payload via `--data` / `--data-length`.

**IPv6 extension-header manipulation (IPv6-only):**
- `--hop` — Hop-by-Hop Options (router alert, jumbo payload, padding, unknown option).
- `--dest` — Destination Options (home address, tunnel encapsulation limit, padding, malformed, unknown).
- `--route` — Routing header (Type 0 with N segments, Type 2/MIPv6, Segment Routing Header, or an invalid type for evasion testing).
- `--ah` — Authentication Header (valid, bad SPI, no ICV, bad length, sequence-number-zero).
- `--esp` — ESP header (valid, bad padding, bad SPI, no IV, malformed).
- `--flow` — IPv6 Flow Label (fixed value, random, or incrementing per packet).
- `--chain` — controls extension-header ordering/duplication (`rand`, `reverse`, `custom:AH,ESP,HBH`, `dup:hop|dest|route|ah[:N]`, `unknown:N`) for evasion/fingerprinting research.
- `--stop` — forces early chain termination (Next-Header = 59, "No Next Header") at a chosen position.

**Ethernet / ARP / L2:**
- `--src-mac` — use a custom source MAC on the wire (Ethernet framing is built explicitly for this, not left to the kernel).
- `--dst-mac` — skip ARP resolution and use an explicit destination MAC.
- `--ether-type` — custom EtherType for ARP frames.
- `--vlan` / `--vlan-stack` — single 802.1Q tag or double-tagged QinQ.
- `--ether-dst-multicast` — send to well-known multicast MACs (ipv4-all, stp, lldp, all-nodes).
- `--ether-padding` — pad ARP frames with extra (fixed or random) bytes.

**Checksum manipulation:**
- Normal, correct TCP checksum.
- `--badsum` for a fully invalid checksum (optional explicit value).
- `--prsum` for partial/varied corruption strategies: lower, upper, bitflip, middle, swap, incremental, pattern, rfc1141, seq-tied, port-tied, carry-break, valid-ish, null, msb, lsb3, walking-bit, entropy, ones-complement, goodbye, timestamp-lie.

**Scan types:**
- SYN (default), FIN, ACK, NULL, XMAS, WINDOW, MAIMON, CWR, ECE, URG, PSH.
- Custom named scans: HANUMAN, KAKABHUSUNDI, GANESH, RAM, GARUD, JATAYU — each a flag combination (see `PacketTask::ScanInfo::get_scan_map()` in scan.hpp).

**Stateful mode (`-G`):**
- Full 4-way TCP handshake and graceful close, run **inside an automatically-managed network namespace** (see §7.7) so the host kernel's own TCP stack cannot inject interfering RSTs. This automates what previously required a manual `iptables` OUTPUT-RST-REJECT rule.
- `--split` (and `--split-ip/-ip6/-gw/-gw6/-mac/-iface`) also exposes this namespace/macvlan isolation as a general-purpose feature, independent of `-G`.

**Fragmentation & evasion:**
- `-f <size>` — IP fragmentation, size must be a multiple of 8 (8–65528).
- `--frag ofo|zof|lap` — out-of-order, zero-offset-last, and overlapping-fragment reassembly-evasion variants.
- `--mtu <value>` — MTU constraint for fragmentation (22–65535).

**Host discovery (ARP + NDP + ICMP):**
- Send batched ARP requests to same-subnet IPv4 targets using AF_PACKET and io_uring (`arp_handler.cpp`), with retry/adaptive-timeout logic.
- Send batched IPv6 Neighbor Discovery (NDP) Neighbor Solicitation/Advertisement sweeps for on-link IPv6 targets (`ndp_neighbor_sweep`, `icmp_ping.hpp`), run alongside the ARP pass.
- `-sn` — ARP/ICMPv4-based alive-host discovery for IPv4 targets.
- `-sn6` — IPv6 alive-host discovery: a target is reported alive if **either** the NDP neighbor sweep **or** an ICMPv6 echo probe succeeds.
- `-Pn` — skip the discovery/ping probe and scan targets unconditionally.
- Static ARP entry management (`set_static_arp_entry` / `delete_static_arp_entry`).

**Service / version detection (`-sV`):**
- Non-blocking connect-and-probe engine (`async_io::Reactor`, epoll-based, sharded across threads) — separate from the raw-packet scan path.
- TCP or UDP probing (`--udp`), banner-grab only (`--force-raw`) or forced HTTP/HTTPS probes (`--force-http`/`--force-https`).
- TLS support: `--tls-verify`, `--tls-ca`, `--tls-ca-path`, `--tls-cert`/`--tls-key` (mTLS), `--tls-sni`.
- `--host` overrides the HTTP Host header; `--sv-timeout` controls response wait; `--verbose` for diagnostics.

**Traceroute (`--traceroute`):**
- IPv4 and IPv6 hop-by-hop tracing with per-hop RTT over multiple probes, reverse-DNS, MPLS label-stack decoding (RFC 4950), GeoIP/ASN/ISP enrichment, plus destination/unreachable detection.

**Anomaly / OS-fingerprint analysis:**
- TTL-based hop-distance and initial-TTL inference (common OS TTL priors: 64/128/255/60/254) with confidence scoring.
- Window-Size-Negotiation (WSN) inconsistency detection across a target's responses.
- Debug-surfaced via `--debug ttl` / `--debug wsn`.

**Port specification:**
- Read ports from `ports.txt` by default; also supports `-p` (list, ranges), `--exclude-ports`.
- `read_ports_from_file()` uses mmap and safely parses very large files.

**Target specification:**
- Single IP/domain, comma-separated list, CIDR expansion, `-iL` file with comments and domain resolution.
- `--trail` (SecurityTrails subdomain enumeration, API key required) and `--enum` (Shodan InternetDB enrichment).
- `--dns-servers` / `--dns-servers-tls` — custom resolvers, including DNS-over-TLS (port 853, certificate-verified).

**Enrichment & DB:**
- Shodan InternetDB fetch for IP (`https://internetdb.shodan.io/<ip>`), formatted via nlohmann::json.
- SecurityTrails fetch (via curl), jq-based parsing when available, fallback JSON parsing implemented.

**Output:**
- Pretty console output with Unicode icons and color-coded states.
- Save results to a file via `-o <file>`. Output is plain text; the format is not currently selected by file extension (see §11).
- `--grep` — plain, copy-friendly grepable target list at scan end.

**Buffer & concurrency:**
- `PacketBufferPool` (thread-local buffers with a moodycamel queue).
- `moodycamel::ConcurrentQueue` for packet tasks and buffer queues.
- Global send/receive io_uring contexts (`GlobalSendCtx`/`GlobalRecvCtx`) shared by worker threads, with a dedicated `recv_reader_thread_func`.

**Debugging:**
- `--debug packet|recv|send|rtt|wsn|ttl|demux|strack` — packet/RTT/anomaly diagnostics, live receive-side demux decisions, and state-transition ("strack") tracing.

**Misc:**
- Reverse DNS lookup with a PTR cache.
- Adaptive RTT learning (`--set-rtt` seed) to tune timeouts.
- ICMP admin-prohibited detection surfaced per-port (`icmp_filter_reasons` / `icmp_warnings` on `RecPross`).
- `RAIIManager` for scoped cleanup, and global emergency cleanup for signals/crashes.
- IP-range provider database lookups (AWS, Cloudflare, Akamai, Azure, DigitalOcean, Google, Alibaba, Fastly, Hetzner, Vultr, Zscaler, Googlebot, Linode, Tor) via `load_ip_range_databases` / `lookup_ip_provider`.
- Local-network diagnostics: interface health (`assess_interface_health`), local firewall detection (iptables/nft), NAT detection, ICMP rate-limit inspection, conntrack lookups, default-route/netlink resolution.

## 4 — Build & runtime quickstart

**Prerequisites:**
- Linux kernel with io_uring support (5.6+ minimum; newer kernels needed for SQPOLL+ATTACH_WQ and some registered-fd behavior).
- g++ with C++17/20, liburing dev, libcurl dev, nlohmann::json dev, OpenSSL dev (needed by the async_io TLS reactor for `-sV`), concurrentqueue header.

**Build:**
- `make`

**Run** (must be root or have CAP_NET_RAW; `--split`/`-G` and namespace features additionally need CAP_NET_ADMIN or root):
- `sudo ./shiv <target> -p <ports> [options]`

**Examples:**
- `sudo ./shiv 192.168.1.71 -p 22,80 -o result.txt`
- `sudo ./shiv 10.0.0.0/24 -t 4 --send-uring 256 --rcv-uring 128 -p 1-1024`
- `sudo ./shiv 2001:db8::1 -p 443 -sS` (IPv6 target)

## 5 — Permissions & safety

- Raw sockets require CAP_NET_RAW or root (sudo). ARP requires AF_PACKET raw sockets.
- `--split` and the automated `-G` namespace isolation create a network namespace plus a macvlan device, and require CAP_NET_ADMIN (in practice: root).
- Scanning without permission may be illegal — only test against systems you're authorized to test.
- Advanced features (badsum, malformed TFO cookies, malformed IPv6 extension headers, AH/ESP corruption modes) can break or trigger IDS/IPS — use in a lab first.

## 6 — High-level architecture & data flow

**Source layout (26 files):**
- Orchestration: `main.cpp`, `handler.cpp`/`handler.hpp`, `parser.cpp`/`parser.hpp`
- Core scan engine: `scan.cpp`/`scan.hpp` (packet build/send/receive, `PacketBufferPool`, global io_uring contexts, congestion tuning)
- ARP: `arp_handler.cpp`/`arp_handler.hpp`
- ICMP & neighbor discovery: `icmp_ping.hpp` (ICMPv4/ICMPv6 echo, NDP neighbor sweep)
- Namespace isolation: `netns_split.cpp`/`netns_split.hpp`
- Version detection: `async_io.cpp`/`async_io.hpp`, `probe.cpp`/`probe.hpp`, `control.cpp`
- Traceroute: `traceroute.cpp`/`traceroute.hpp`
- Anomaly analysis: `anomaly_analysis.cpp`/`anomaly_analysis.hpp`
- Debug output: `debug.cpp`/`debug.hpp`
- Public DB enrichment: `public_db.cpp`/`public_db.hpp`
- Shared utilities: `utils.cpp`/`utils.hpp`

**Components:**
- CLI/Orchestrator (`main.cpp`, `handler.cpp`): parse args (`parser.cpp`), read targets & ports, decide whether to enter a split namespace, size/spawn worker threads, wire up global io_uring send/recv contexts.
- Worker threads: each assigned a subset of IPs; run `thread_worker` (`handler.cpp`) to process host(s), using the shared `GlobalSendCtx`/`GlobalRecvCtx` rather than a private ring.
- Per-host scanning flow:
  - Prepare port batches, then call `receive_response` for a batch. Inside `receive_response` (`scan.cpp`), packets are built (`build_packet`) and handed to `send_tcp_packets`, which submits into the global send ring (or a per-batch ring when global contexts aren't in play). The global receive path (`recv_reader_thread_func` / per-target receive queues) delivers matching replies, which are parsed and passed to `process_response`.
  - Collect `RecPross` and aggregate outputs.
- ARP/NDP pre-resolution: for same-subnet IPv4 targets, `arp_handler.cpp`'s `send_arp_request`/`receive_arp_reply` populate MAC addresses before scanning starts; for on-link IPv6 targets, an NDP neighbor sweep (`icmp_ping.hpp`) runs the equivalent pass.
- Version detection (`-sV`): a completely separate, non-blocking path. `probe.cpp` builds `async_io::Operation`s and hands them to the shared `async_io::Reactor` (epoll-based, TLS-aware); `control.cpp` implements the connection/response-handling layer on top of it — `run_version_probe`, TLS certificate extraction, and HTTP response parsing.
- Traceroute: `traceroute.cpp` runs its own ICMP/UDP TTL-ramp probing sequence, independent of the port-scan engine, with optional GeoIP/reverse-DNS enrichment.
- Namespace isolation: `netns_split.cpp` can create an isolated network namespace with a macvlan device, and execute the scan logic inside it (the process forks and enters the namespace via `setns`; it does not re-exec the binary), and/or install a temporary outbound-RST-block rule — automating what used to be a manual `iptables` step for `-G`.
- Utilities: service mapping, ports parsing, MAC vendor mapping, reverse DNS, IP-range provider databases, interface/route/firewall/NAT introspection (`utils.cpp`).

**Data flow:**
1. Targets & ports are enumerated in `main.cpp`/`handler.cpp`.
2. For each batch, `PacketTask` objects are created and queued.
3. The sender builds raw packets in `PacketBufferPool` buffers and submits io_uring sends (global ring, optionally SQPOLL).
4. The receiver reads raw packets via the global recv context, parses them, and maps them to `PortState`/`PacketDetails` and result lists; ICMP admin-prohibited replies are classified separately.
5. Aggregated results are printed and optionally saved; anomaly analysis (TTL/WSN) and traceroute output are layered on top when requested.

## 7 — Core components deep-dive

### 7.1 io_uring — primer & current usage
**Primer:**
- io_uring provides a submission queue (SQ) and completion queue (CQ) shared between user and kernel via a memory-mapped ring.
- Typical calls: `io_uring_queue_init`/`io_uring_queue_init_params`, `io_uring_get_sqe`, `io_uring_prep_sendmsg`/`io_uring_prep_recvmsg`, `io_uring_submit`, `io_uring_peek_cqe`/`io_uring_wait_cqe(_timeout)`/`io_uring_cqe_seen`.

**Current usage:**
- Send and receive go through **global, shared contexts** — `GlobalSendCtx` and `GlobalRecvCtx` (scan.hpp) — rather than each `thread_worker` owning a private ring. A dedicated `recv_reader_thread_func` drains the shared receive ring and routes completions back to the right in-flight target/port.
- Rings are set up with `IORING_SETUP_COOP_TASKRUN | IORING_SETUP_SINGLE_ISSUER` where available (see `init_ring_with_flags` in handler.cpp), falling back to plain `io_uring_queue_init` on older kernels.
- **SQPOLL**: auto-enable is hybrid — with adaptive/dynamic rate or batch-delay pacing (the default), it triggers when probe volume (hosts × ports) crosses `--sqpoll-threshold` (default 300000); with fixed/non-dynamic pacing, it instead triggers when `estimate_scan_duration_ms` predicts a scan duration ≥8s. Either way, or when `--sqpoll` is forced, the global send/recv rings are initialized with `IORING_SETUP_SQPOLL`, first attempting `IORING_SETUP_ATTACH_WQ` to share the poller thread between the send and receive rings, falling back to a plain SQPOLL ring, and finally to a non-SQPOLL ring if that also fails.
- **Registered/fixed file descriptors**: sockets are registered with the ring (`*_fixed_idx` members on the global contexts) so `io_uring_prep_sendmsg`/`recvmsg` can address them without a per-call fd lookup — both TCP and TCP6/ICMP/ICMPv6 sockets have fixed-index variants alongside the plain-fd path.
- ARP send/receive (`arp_handler.cpp`) still uses `io_uring_prep_recvmsg` on an AF_PACKET socket for batched ARP requests.

### 7.2 async_io Reactor (powers `-sV`)
- A self-contained, epoll-based, multi-shard, non-blocking connect/TLS/send/recv engine (`async_io.hpp`/`.cpp`), completely separate from the raw-packet io_uring path.
- `Operation` describes one TCP/TLS/UDP probe (target, payload, timeouts, TLS options, optional fixed source port); `Reactor` drives it through `CONNECTING → TLS_HANDSHAKE → SENDING → RECV_FIRST → RECV_IDLE → DONE` stages across a pool of `EpollShard`s (one epoll fd + worker thread per shard).
- Adaptive connect-timeout budgeting per shard based on a rolling RTT sample window (`kRttSampleWindow = 32`).
- `run_blocking()` provides a synchronous convenience wrapper over the async reactor for callers (e.g. `control.cpp`) that want a blocking-style API; `shared_reactor()` exposes a process-wide singleton reactor.
- Used exclusively by the `-sV` service/version-detection path — it is not part of the SYN/FIN/etc. scan engine.

### 7.3 moodycamel::ConcurrentQueue (why & how)
- A high-performance lock-free queue used for:
  - The per-thread buffer queue (`PacketBufferPool::buffer_queue`).
  - PacketTask queues used to decouple producers (port-state/timeout logic) from senders.
- Bulk dequeue (`try_dequeue_bulk`) is used to build send batches efficiently.

### 7.4 PacketBufferPool (design & usage)
- Purpose: minimize heap allocations per packet by reusing pre-allocated fixed-size buffers.
- Strategy:
  - A thread_local `buffers` vector — each thread owns a set of `vector<char>` buffers.
  - A thread_local moodycamel queue of `char*` pointers to available buffers.
  - Pool sizing is heuristic (scales with ports/threads) and tunable via `--buf-peak` (peak over-allocation factor, default 1.3).
- `acquire()` / `release()` follow a lazy-init, dequeue-or-allocate, enqueue-on-release pattern.
- Integration with io_uring: buffer pointers travel via `io_uring_sqe_set_data`/`io_uring_cqe_get_data`, but now against the shared global rings rather than a private one.

### 7.5 Packet lifecycle (end-to-end)
1. A `PacketTask` is created — dual-stack, carrying both a `sockaddr_in` and a `sockaddr_in6`, selected by `is_ipv6` — with destination, src port, seq, flags, and every TCP-option/checksum/TFO/AO field.
2. The sender dequeues tasks, acquires buffers, and calls `build_packet` to populate IP(v4/v6)/TCP headers, extension headers (IPv6), options, and payload.
3. `send_tcp_packets` prepares a msghdr/iovec for each packet and submits via the global io_uring send context (fixed-fd where available) in batches, falling back to `sendmsg` if needed.
4. `receive_response` (per target/batch) waits on completions routed from the shared receive context; when a response arrives it's parsed into `PacketDetails`, and `process_response` classifies the port.
5. `process_response` updates `RecPross` (open/closed/filtered, plus ICMP filter-reason detail) and may enqueue follow-up packets (ACK/FIN, or namespace-mediated handshake continuation for `-G`).

### 7.6 ARP & NDP handling (arp_handler.cpp, icmp_ping.hpp)
- For same-subnet IPv4 targets (via `autodetect_interface`/netmask/route logic in utils.cpp), the worker pre-resolves MAC addresses:
  - `send_arp_request` batches AF_PACKET requests over io_uring.
  - `receive_arp_reply` listens with configurable retries and min/max round-timeout, filling MAC buffers and optional per-host RTT samples.
  - `set_static_arp_entry`/`delete_static_arp_entry` can pin/clear neighbor-table entries.
  - Results feed `mac_address` on `RecPross` and vendor lookup via a loaded `mac-vendor.txt` map.
- For on-link IPv6 targets, `ndp_neighbor_sweep()` (`icmp_ping.hpp`) sends batched Neighbor Solicitations and collects Neighbor Advertisements to determine liveness, mirroring the ARP pass. For `-sn6`, a target is reported alive if either the NDP sweep or an ICMPv6 echo probe succeeds.

### 7.7 Network-namespace isolation & automated RST blocking (netns_split.cpp)
- `-G` (stateful handshake) automatically runs inside an isolated environment rather than requiring the operator to hand-apply an `iptables` OUTPUT-RST-REJECT rule:
  - `enter_split_namespace(SplitNsConfig)` creates a new network namespace and a macvlan device (default name `shivmv0`), configured with the given MAC/IP/gateway (v4 and/or v6), and continues execution inside that namespace via `fork`/`setns` — the binary is not re-executed.
  - `RstBlockGuard` is a scope guard around `block_outbound_rst()`/`unblock_outbound_rst()` — it installs the outbound-RST-block rule for the duration of the scan and removes it automatically on scope exit (including on crash paths, via the same guard/RAII discipline used elsewhere).
  - `g_in_split_ns` / `g_split_ns_entered_at_ms` are process-wide flags other code paths (e.g. help text, `-G` description) check/report.
- `--split` and its `--split-ip/-ip6/-gw/-gw6/-mac/-iface` options expose the same isolation as a general, user-selectable feature, independent of `-G`.
- `load_split_conf()` can read a persisted split configuration from `/usr/share/shiv/shiv_split.conf` (`kDefaultSplitConfPath`) instead of requiring all namespace parameters on the command line every run.
- This closes the "kernel RST interference" gap that previously required a manual, cautioned-use `iptables` workaround; that manual procedure is no longer the primary path.

### 7.8 IPv6 extension-header manipulation (parser.cpp, IPv6-only options)
- `Ipv6ExtHeaderOptions` (built up by `parse_hop_option`/`parse_dest_option`/`parse_route_option`/`parse_ah_option`/`parse_esp_option`/`parse_flow_option`/`parse_chain_option`/`parse_stop_option` in parser.cpp) drives construction of Hop-by-Hop, Destination Options, Routing (Type 0 / Type 2 / SRH), Authentication, and ESP extension headers, with deliberate corruption modes (bad SPI, no ICV/IV, bad length/padding, sequence-zero) for stack-fingerprinting and evasion research.
- `--chain` controls extension-header ordering (`rand`, `reverse`, a `custom:` explicit order, or `dup:` to repeat a header type) and `--stop` forces early chain termination via Next-Header = 59.
- These options only apply to IPv6 targets; they are rejected/no-ops against IPv4 targets.

### 7.9 Traceroute (traceroute.cpp)
- `run_traceroute`/`run_traceroute6` perform a classic TTL-ramp probe sequence (`TracerouteOptions`: max_hops default 30, probes_per_hop default 3, per-probe timeout default 1000ms), building a `TracerouteHop` per TTL with:
  - Per-probe RTTs (`TracerouteProbe`), reverse-DNS (reusing the shared PTR cache from utils.hpp) when `resolve_dns` is set.
  - MPLS label-stack decoding (`MplsLabelEntry`, RFC 4950 ICMP extensions) when present.
  - GeoIP/ASN/ISP enrichment (`GeoIspInfo`) when `resolve_geoip` is set.
  - Destination/unreachable flags.
- Invoked via `--traceroute`; output rendered by `print_traceroute_results`.

### 7.10 Anomaly / OS-fingerprint analysis (anomaly_analysis.cpp)
- TTL analysis: infers the likely initial TTL (`infer_initial`, weighted priors for Linux/BSD/macOS/Android=64, Windows=128, Solaris/network-gear=255, and lower-confidence 60/254 variants) and estimated hop distance from an observed TTL, with a confidence score derived from the gap between the best- and second-best-matching prior. Surfaced via `display_ttl_analysis` / `--debug ttl`.
- WSN (window-size-negotiation) analysis: flags inconsistent window-size behavior across a target's responses via `display_wsn_analysis` / `--debug wsn`.
- Internally uses robust statistics (median/MAD-based z-scores, quantiles, entropy/Gini helpers) to avoid being thrown off by a handful of outlier samples, and a bounded per-target history store (`TargetHistoryStore`) so long scans don't grow memory unbounded.

### 7.11 Checksum strategies (scan.cpp `build_packet`)
- Normal: computed pseudo-header + TCP segment sum.
- `--badsum`: explicit or auto-generated bad checksum.
- `--prsum`: the full set of partial-corruption strategies listed in §3, each producing a different, deliberately "almost right" checksum for stack-fingerprinting.

### 7.12 TCP options, TFO, TCP-AO, MPTCP
- Standard options (MSS/WS/SACK/Timestamp/NOP) build and auto-align.
- TFO cookie injection (`--inj-tfo-cookie`, alias `--inject-tfo-cookie`): `len:N` (random, N odd, ≥5), `str:S`, `hex:H`.
- **TCP-AO** (`--tcp-ao <kid:rnext:maclen>`, default `1:1:12`) — adds a TCP Authentication Option (kind 29).
- **MPTCP** (`--tcp-mtcp`) — adds an MP_CAPABLE option (kind 30).

### 7.13 Service/version detection (`-sV`)
- Enabled with `-sV`; everything else in this group (`--sv-timeout`, `--udp`, `--force-raw`, `--force-http`, `--force-https`, `--tls-*`, `--host`, `--verbose`) is ignored unless `-sV` is present.
- `probe.cpp`/`probe.hpp` build the probe request and hold the signature-matching engine, on top of the `async_io::Reactor` from §7.2. `control.cpp` implements the actual connect-and-probe orchestration (`run_version_probe`), TLS certificate extraction, and HTTP response parsing (status/title/redirect/SPA-redirect/body decompression), and classifies the service/banner against a user-editable signature set loaded by `load_signature_config()` from `signatures.conf`.

## 9 — Important data structures & their field-level meanings

(Defined primarily in scan.hpp; this section lists notable groups of fields rather than reproducing every line. Several of these structs are dual-stack (IPv4/IPv6) aware.)

- `enum class ScanType { SYN, FIN, ACK, NULL_SCAN, XMAS, WINDOW, MAIMON, CWR, ECE, URG, PSH, HANUMAN, KAKABHUSUNDI, GANESH, RAM, GARUD, JATAYU }` — drives TCP flags and expected-response logic via `PacketTask::ScanInfo::get_scan_map()`.

- `struct PacketDetails` — parsed detail of a received packet:
  - Core fields: port, tcp_flags, seq/ack, window_size, window_scale, sack_permitted, tsval/tsecr, tfo_data, payload, checksum, ip_id, ttl, has_* flags.
  - Raw capture: `raw_packet`, `ip_total_length`, `ip_header_len`, `tcp_header_len`, `src_ip`/`dst_ip`, `src_port`/`dst_port`, `capture_epoch_us`.
  - Probe context: `retry_index`, `rtt_ms`, `sent_ttl`, `sent_ws`, `sent_tsval`, `sent_flags`.
  - Extra IP header detail: `ip_tos`, `ip_frag_off_raw`, `ip_mf_flag`, `ip_protocol`, `ip_checksum`, `ip_checksum_valid`.
  - Extra TCP header detail: `tcp_data_offset`, `tcp_reserved_bits`, `tcp_urg_ptr`, `tcp_checksum_valid`.
  - Raw/parsed TCP options: `tcp_options_raw`, `tcp_payload_raw`, `payload_len`, `tcp_option_layout`, `has_mss`/`mss_value`, `has_eol`/`eol_offset`, `has_unknown_options`/`unknown_option_kinds`, `has_sack_blocks`/`sack_blocks`.
  - Timing: `kernel_rx_ts_us`, `user_rx_ts_us`, `tx_ts_us`, `rtt_ewma_ms`, `rtt_jitter_ms`, `rtt_outlier`, `ttl_outlier`, `hop_distance_est`.
  - Probe identity/classification (feeds anomaly analysis and signature matching): `flow_hash`, `probe_id`, `response_index`, `duplicate_response`, `retransmission_suspect`, `classification_reason`, `signature_tags`, `anomaly_score`, `anomaly_confidence`.
  - What-was-sent mirror: `sent_window_size`, `sent_mss`, `sent_seq`, `sent_ack`, `sent_dscp`, `sent_ip_tos`, `sent_ip_id`, `sent_df`, `sent_sack_permitted`.

- `struct SentPacketDetails` — a TX-side mirror of `PacketDetails`, populated in `build_packet()`, capturing what was actually built/queued to send (IP/TCP header fields as sent) rather than what came back; used for `--debug send`.

- `struct RecPross` — per-target scan result:
  - `closed_ports` (int), `open_ports` / `filtered_ports` (vector<uint16_t>).
  - `icmp_filter_reasons` (per-port ICMP admin-prohibited reason) and `icmp_warnings` — lets "filtered" be explained rather than just asserted.
  - `mac_address`, `learned_rtt_ms`, `packet_details` (map<port, PacketDetails>), `packets_sent`, `received_ttl`.
  - `rtt_debug_entries`, `demux_debug_entries`/`demux_counts`, `strack_entries`/`strack_counts` — feed the `--debug rtt|demux|strack` output.
  - `output_buffer` — accumulated formatted output for the target.

- `struct PortState` — per-port state-machine bookkeeping: `src_port`, `seq`/`ack_seq`, `connection_established`, `fin_sent`/`fin_ack_received`, `start_time`, `retry_count`/`timeout_ms`/`retries_cap`, `rtt_measured`/`syn_sent_time`/`sent_tsval`/`ewma_rtt`, `final_state_determined`, `reported_state` (`PortReportedState::None/Open/Closed/Filtered`), plus a small fixed-size (6-entry) record of which source ports were used on which attempt (`used_src_ports`, `used_src_port_attempt`, `used_src_port_count`) and helper methods `record_src_port`/`attempt_for_src_port`/`accepts_src_port` supporting the `-g`/`--sport-range` per-attempt source-port controls.

- `struct PacketTask` — dual-stack: carries both `sockaddr_in dest` and `sockaddr_in6 dest6`, selected via `is_ipv6`. Holds src_port/seq/ack/flags/data/scan_type/dest_port and the full set of TCP-option/checksum/TFO fields (window_scale, mss_value, timestamps, nops_count, sack_permitted, badsum/partial-badsum fields, TFO cookie fields). `ScanInfo::get_scan_map()` and `get_rst_expecting_scans()` hold the static scan-type → flags/behavior table. Move-only, optimized for queueing.

- `struct GlobalSendCtx` / `struct GlobalRecvCtx` (scan.hpp) — the shared io_uring send/receive contexts described in §7.1: hold the ring(s), registered/fixed socket indices for TCP/TCP6/ICMP/ICMPv6, and SQPOLL state (`sqpoll_active`).

- `struct Ipv6ExtHeaderOptions` (parser.hpp/scan.hpp) — accumulates the IPv6 extension-header configuration parsed from `--hop`/`--dest`/`--route`/`--ah`/`--esp`/`--flow`/`--chain`/`--stop`.

- `struct TracerouteHop` / `TracerouteProbe` / `MplsLabelEntry` / `GeoIspInfo` / `TracerouteOptions` (traceroute.hpp) — see §7.9.

- `struct SplitNsConfig` / `SplitFileConf` / `RstBlockGuard` (netns_split.hpp) — see §7.7.

- `struct async_io::Operation` / `Reactor` / `TlsOptions` / `Timeouts` / `SourcePort` (async_io.hpp) — see §7.2.

- `struct CongestionTuneConfig` (`g_cong_tune`, scan.hpp/scan.cpp) — the congestion/rate-limit tuning knobs described in §3 and §14 (retry-delay bounds, RTO multiplier/padding, congestion-curve exponent and alpha-up/down, buffer-pool peak factor, batch-settle time, SQPOLL fallback probe-volume threshold — used only when pacing is adaptive/dynamic).

## 10 — File-by-file summary

- `main.cpp` — top-level entry: loads config (via `parser.cpp`), the MAC-vendor map, registers signal handlers, decides whether to enter a split namespace, sizes SQPOLL/global io_uring contexts via a hybrid check (`estimate_scan_duration_ms` when pacing is fixed/predictable, `SQPOLL_FALLBACK_VOLUME`/`g_cong_tune.sqpoll_threshold` probe-volume check when pacing is adaptive/dynamic), spawns worker threads, aggregates and saves results.
- `control.cpp` — the largest single file (~5.3k lines); implements the `-sV` service/version-detection engine's connection and response-handling layer, built on top of `async_io::Reactor` (async_io.hpp) and `probe.hpp`'s signature-matching engine: `run_version_probe`, TCP/TLS response capture, TLS certificate extraction (`extract_tls_cert_info`), HTTP response parsing (status/title/redirect/SPA-redirect/body decompression), and signature-config loading (`load_signature_config`). It is not the CLI-orchestration or congestion-tuning file — those responsibilities live in `parser.cpp`/`handler.cpp` and `scan.cpp`/`scan.hpp` (`g_cong_tune`) respectively.
- `handler.cpp`/`handler.hpp` — `thread_worker` (the per-thread scan loop), terminal/help output (`print_full_help`, the full CLI reference text), DNS resolution helpers, IP list/CIDR/file processing, `TargetLocality` assessment (on-link/same-network/virtual-interface classification), grepable output, `save_scan_results`, emergency cleanup and signal handling, and the io_uring ring-init helper (`init_ring_with_flags`, COOP_TASKRUN/SINGLE_ISSUER).
- `parser.cpp`/`parser.hpp` — parses the numerous structured option values: sport-range, gsport, durations (`parse_duration_to_us`), rate/jitter/batch-delay/bandwidth configs, packet-length, DSCP/TOS, IP-ID mode, and all the IPv6 extension-header option grammars (hop/dest/route/ah/esp/flow/chain/stop).
- `scan.cpp`/`scan.hpp` — the core scan engine:
  - `PacketBufferPool` implementation.
  - `build_packet` — constructs IPv4/IPv6 + TCP headers, extension headers, options, payload; computes/corrupts checksums; handles TFO/TCP-AO/MPTCP.
  - `send_tcp_packets` — builds and submits packets via the global send context (or `sendmsg` fallback).
  - `receive_response` / `recv_reader_thread_func` — receive-side processing against the global receive context; `process_response` classifies port state per scan type, including ICMP admin-prohibited detection.
  - `GlobalSendCtx`/`GlobalRecvCtx` setup, including SQPOLL/ATTACH_WQ negotiation.
  - `CongestionTuneConfig`/`g_cong_tune` — congestion/rate-limit tuning state (see §9, §14).
  - `worker_thread`-level per-IP orchestration and result printing (`print_output`).
- `arp_handler.cpp`/`arp_handler.hpp` — `send_arp_request`/`receive_arp_reply` (moved out of scan.cpp), `set_static_arp_entry`/`delete_static_arp_entry`.
- `netns_split.cpp`/`netns_split.hpp` — namespace/macvlan setup (`enter_split_namespace`): creates a network namespace and a single macvlan device (default `shivmv0`), moves it into the namespace, assigns MAC/IP/gateway, and brings it up; split-config file loading (`load_split_conf`, `/usr/share/shiv/shiv_split.conf`); and the automated outbound-RST-block guard (`RstBlockGuard`, `block_outbound_rst`/`unblock_outbound_rst`) used by `-G`/`--split`.
- `async_io.cpp`/`async_io.hpp` — the epoll-based non-blocking `Reactor`/`Operation` engine used only by `-sV` (see §7.2).
- `probe.cpp`/`probe.hpp` — builds `-sV` probe payloads (HTTP/HTTPS/raw/UDP) and holds the signature-matching engine consumed by `control.cpp`'s `run_version_probe`.
- `icmp_ping.hpp` — ICMP echo/ping support used by discovery (`-sn`) and traceroute-adjacent paths, plus IPv6 neighbor discovery (`ndp_neighbor_sweep`, NDP Neighbor Solicitation/Advertisement) used by `-sn6` (large header-only implementation, ~1.3k lines).
- `traceroute.cpp`/`traceroute.hpp` — `run_traceroute`/`run_traceroute6`, MPLS decoding, GeoIP enrichment, `print_traceroute_results` (see §7.9).
- `anomaly_analysis.cpp`/`anomaly_analysis.hpp` — TTL and WSN anomaly detection/display (see §7.10); also home to several robust-statistics helpers (median/MAD/quantile/entropy) and the private-IP/TTL-prior tables used there.
- `debug.cpp`/`debug.hpp` — `print_rtt_debug`, `print_demux_debug`, `print_strack_debug` — the renderers behind `--debug rtt|demux|strack`.
- `public_db.cpp`/`public_db.hpp` — `fetch_shodan_info`/`display_shodan_info` (InternetDB), `fetch_subdomains_from_api`/`fetch_subdomains_from_api_no_jq` (SecurityTrails).
- `utils.cpp`/`utils.hpp` — shared building blocks: `checksum`, `parse_ports`/`read_ports_from_file` (mmap-based), `read_services_from_file` (mmap-based), `get_ip_version`, `make_sockaddr_from_ip`, `autodetect_interface` (v4/v6), interface MAC/IP/netmask/prefix accessors, IPv6 scope classification, PTR-cache-backed `reverse_dns_lookup`, `route_lookup`/`get_default_route` (netlink-based; the default-route lookup deliberately avoids probe-address tricks), neighbor-cache/conntrack/NAT/local-firewall/interface-health introspection, and the IP-range provider database loader/lookup (`load_ip_range_databases`/`lookup_ip_provider`) covering AWS/Cloudflare/Akamai/Azure/DigitalOcean/Google/Alibaba/Fastly/Hetzner/Vultr/Zscaler/Googlebot/Linode/Tor.
- `Makefile` — builds with g++, `-std=c++17`/`c++20`-class flags, `-pthread -march=native -O3 -mavx2 -D__AVX2__`, hardening flags (`-fstack-protector-strong -D_FORTIFY_SOURCE=2 -fPIE -pie -Wl,-z,relro,-z,now`), links `-luring -lcurl -lpthread -lssl -lcrypto` (OpenSSL required for the `-sV` TLS reactor); target binary `shiv`.
- `ports.txt` — default port list used when `-p` is omitted.
- `services` — service-name/port/protocol map (TCP entries loaded).
- `mac-vendor.txt` — OUI → vendor mapping.
- `signatures.conf` — user-editable header/tag/regex signature definitions consumed by `load_signature_config()` for `-sV` service classification.

## 11 — Output formats & enrichment

- Console output: `print_output()`-style rendering with per-port state, RTT/anomaly info, MAC address, thread/scan summaries, and traceroute/OS-fingerprint sections when requested.
- File output (`-o <file>`, via `save_scan_results`): writes a single plain-text summary of results (or the captured console log, if one was recorded) to the given path. **The output format is not currently selected by file extension** — passing `results.json`, `results.xml`, or `results.csv` produces the same plain-text content as `results.txt`; there is no JSON/XML/CSV serializer today. Treat multi-format output as a documented gap rather than an implemented option.
- `--grep` — plain grepable target list at the end of the scan.
- Shodan/InternetDB: `fetch_shodan_info` (libcurl) + `display_shodan_info` (nlohmann::json) — ASN, org, country, hostnames, ports, tags, vulnerabilities.
- SecurityTrails: `fetch_subdomains_from_api` (curl+jq) with a fallback naive-JSON-parse implementation when `jq` isn't available.

## 12 — Concurrency, thread model & resource tracking

- Top-level threads: `main`/orchestration spawns up to `config.num_threads` worker threads, each owning a subset of IPs.
- Send/receive concurrency centers on the **global** `GlobalSendCtx`/`GlobalRecvCtx` (§7.1) rather than a private ring per worker: worker threads submit into the shared send context, and a dedicated `recv_reader_thread_func` fans completions back out.
- `-sV` runs its own concurrency domain entirely: the `async_io::Reactor`'s `EpollShard`s, each with its own thread, independent of the raw-packet worker threads.
- Synchronization: `cout_mutex` for serialized printing, atomic `terminate_flag` for cooperative shutdown, `RAIIManager`/`RstBlockGuard`-style scope guards for cleanup, and global-resource tracking (sockets, io_uring rings, threads) for the emergency-cleanup path.

---

## 13 — Error handling, signals & emergency cleanup

- Signals registered: SIGINT, SIGSEGV, SIGABRT, SIGTERM, SIGFPE, SIGBUS, SIGILL, SIGSYS, SIGPIPE, SIGXCPU, SIGXFSZ.
- SIGINT sets `terminate_flag` for a graceful stop; other fatal signals trigger `emergency_cleanup` and re-raise the default handler.
- `emergency_cleanup` also tears down any active split namespace / RST-block rule (`g_in_split_ns`), so a crash mid-`-G`/`--split` scan doesn't leave the namespace or firewall rule behind.
- `read_ports_from_file`/`read_services_from_file` use mmap with RAII-style guards for `munmap`/`close`.

## 14 — Performance tuning (all knobs & recommendations)

- `-t` (num_threads): per-host concurrency; increase for many hosts, watch NIC/CPU capacity.
- `--send-uring`/`--rcv-uring`: global io_uring depths (allowed set as in §8); larger improves throughput at the cost of memory.
- `--sqpoll` / `--sqpoll-threshold`: force, or auto-enable kernel-thread submission — for adaptive/dynamic pacing (default), once hosts × ports crosses `--sqpoll-threshold` (default 300000); for fixed/non-dynamic pacing, once estimated duration reaches 8s. Reduces `io_uring_enter` syscall volume, but note it adds a dedicated poller thread whose own overhead can outweigh that benefit on short (single-host, sub-4s) scans.
- `--rate` / `--rate-dyn-min/max/window`: hard or adaptive packet-rate ceilings.
- `--jitter`, `--batch-delay` / `--batch-delay-dyn-min/max`, `--bandwidth`: pacing controls to avoid overwhelming the local NIC or being fingerprinted as a burst scanner.
- `--retry-delay-min/max`, `--retry-delay-floor-div`, `--cong-curve`, `--cong-alpha-up/down`, `--rto-mult`, `--rto-pad1/2`: shape how aggressively retries back off under observed congestion/loss.
- `-b <size>`: port batch size (default 250).
- `--rcvbuf`: socket receive buffer size; increase for high-rate scanning to avoid dropped replies.
- `--buf-peak`, `--batch-settle`: PacketBufferPool over-allocation and io_uring batch-submit settle time.
- `--set-rtt`: seed the adaptive RTT/timeout learner instead of starting cold.

**Practical steps:**
1. Start small: 1–2 threads, `--send-uring 64 --rcv-uring 64`.
2. Run local tests with tcpdump and monitor `/proc/net/netstat` and NIC queue stalls.
3. Increase uring depths in increments; watch for kernel CPU or packet loss.
4. For multi-host scans with default adaptive pacing, let `--sqpoll-threshold` (default 300000 hosts×ports) auto-enable SQPOLL; for scans with fixed pacing, it auto-enables based on estimated duration (≥8s) instead. A single host's max possible volume is 65535 (one full port range), which alone never crosses the default threshold — SQPOLL only auto-triggers there via the duration path or `--sqpoll` forced.
5. Use `--rate`/`--jitter`/`--batch-delay`/`--bandwidth` (or their `-dyn-*` adaptive variants) to stay polite on shared or monitored networks.

## 15 — Testing, debugging & capture tips

- Capture packets: `sudo tcpdump -i <iface> -w capture.pcap host <target_ip>`; use Wireshark for TCP-option/IPv6-extension-header analysis.
- `--debug <mode>` covers: `packet`/`recv`/`send` (raw packet detail — `send` uses the `SentPacketDetails` mirror), `rtt` (RTT calculations), `wsn`/`ttl` (anomaly analysis), `demux` (live receive-side matched/dropped/replies decisions with a per-batch summary), `strack` (state-transition tracing, useful for seeing ports reclassified on retry).
- Common troubleshooting:
  - `io_uring_queue_init`/`_params` failure → check liburing and kernel version; SQPOLL+ATTACH_WQ needs a newer kernel than plain io_uring.
  - Socket creation failure → ensure CAP_NET_RAW/root.
  - `-G`/`--split` failing to enter the namespace → ensure CAP_NET_ADMIN/root and that the base interface (`--split-iface` or autodetected) supports macvlan.
  - No replies → verify the local route, that the target isn't NAT'd in a way that blocks raw replies, and check `--debug demux` to see whether replies are arriving but being dropped/misrouted.
  - ARP failures → confirm interface IP/netmask (`autodetect_interface`) and AF_PACKET support.
  - `-sn6` reporting a live IPv6 host as down → check that NDP is not being blocked (`ndp_neighbor_sweep` needs the same L2 reachability as ARP) before assuming ICMPv6 alone is authoritative.
  - `-sV` TLS failures → check `--tls-ca`/`--tls-ca-path`, and try without `--tls-verify` first to isolate cert-trust issues from connectivity issues.

## 16 — Security, legal & operational considerations

- Legal: scanning without authorization is potentially illegal and unethical.
- Operational impact: aggressive scanning can saturate networks, trigger IDS/IPS, and generate audit logs on targets; the pacing controls (§14) exist specifically to let an operator dial this down.
- Malformed packets, checksum manipulations, and malformed IPv6 extension headers/AH/ESP can crash buggy stacks — use on lab networks first.
- `--split`/`-G` namespace isolation and the automated RST-block rule are host-level, temporary changes (scoped and auto-reverted) — understand what they do before running on a shared host.
- Avoid scanning cloud providers without permission — many have strict scanning policies (the built-in IP-range provider database, §3/§10, can help you recognize when a target belongs to one).

## 17 — Appendix: example commands & workflows

1. Basic SYN scan: `sudo ./shiv 192.168.1.71 -p 22,80`
2. CIDR scan with more concurrency: `sudo ./shiv 10.0.0.0/24 -t 4 -b 250 --send-uring 256 --rcv-uring 128`
3. SecurityTrails subdomain enumeration + scan: `sudo ./shiv example.com -p 22 --trail <api-key>`
4. Save results to a file (plain text regardless of extension): `sudo ./shiv 192.168.1.71 -p 22,80 -o results.txt`
5. Graceful handshake (namespace-isolated automatically): `sudo ./shiv 198.51.100.12 -p 22 -G`
6. Inject a TFO cookie (string): `sudo ./shiv 203.0.113.5 -p 80 --inj-tfo-cookie str:hacker`
7. Partial bad checksum: `sudo ./shiv 203.0.113.5 -p 80 --prsum bitflip`
8. IPv6 target with a Hop-by-Hop router-alert option: `sudo ./shiv 2001:db8::1 -p 443 -sS --hop alert:1`
9. Version/service detection over TLS with a custom CA: `sudo ./shiv example.com -p 443 -sV --force-https --tls-verify --tls-ca ca.pem`
10. Traceroute with GeoIP/ASN enrichment: `sudo ./shiv 8.8.8.8 --traceroute`
11. Isolated-namespace scan with an explicit macvlan IP: `sudo ./shiv 10.0.0.5 -p 80 --split --split-ip 10.0.0.200/24 --split-gw 10.0.0.1`
12. Adaptive pacing to stay polite on a shared network: `sudo ./shiv 10.0.0.0/24 -p 1-1024 --rate 500ms:300-500 --jitter --batch-delay 20ms-30ms`
13. IPv6 on-link host discovery via NDP: `sudo ./shiv 2001:db8::/64 -sn6`
